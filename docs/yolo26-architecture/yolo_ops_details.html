YOLO26n: operations, work and data per block

Date: 16 October 2026, Version: 1.2, Last edit time: 09:43 AEDT, 19 October · pairs with yolo_architecture.html, version 1.2

An index of the blocks in the architecture diagram, for YOLO26n at a 640×640 input. The chart compares the blocks; each block card opens a page with its structure, the memory it holds step by step, and every operation with its shapes and counts. The operations are defined in the table below, with sources at the end. All counts are computed from the YOLO26n layer shapes [1] and the module code [9]; the totals are for the fused model with one set of detection heads (P3, P4 and P5; both sets have the same size).

Bytes shown for: Applies to every byte figure on this page and is remembered across pages. int8: 8-bit integer; bf16: 16-bit brain floating point; fp16, fp32: 16-bit and 32-bit floating point; bfp16: block floating point. kB = 1,000 bytes, MB = 1,000,000 bytes. Weights are counted after batch normalisation is folded in: one weight per kernel entry plus one bias per output channel.*Note: for the bf16 and bfp16 definitions, see AMD Quark documentation: BF16 (bfloat16) and BFP16 (block floating point).

Work and data per block

Figure 2 – Work and data per block, YOLO26n

Totals: 2,740,153,600 multiplications (2,678,713,600 in the 102 convolutions + 61,440,000 in the 4 attention matrix products), that is 5.48 billion operations counting 2 per multiply-add; Ultralytics publishes 5.5 GFLOPs [2]. Weights: 2,408,932 values, matching the published 2.4 million [2]; before batch normalisation is folded in, as trained with both sets of detection heads, the model has 2,572,280 parameters [1].

The totals include one set of three detection heads (P3, P4 and P5). YOLO26 has two such sets, one-to-one and one-to-many, with the same structure and size; a fused model keeps only one, so the totals are the same whichever set is used. See Heads P3–P5 and One-to-many heads. The published figures are explained under 'Note on published figures' on the diagram page.

Definitions of operations

x is the input, y the output. Cin, Cout: input and output channels. H, W: rows and columns. Indices start at 0.

OperationDefinitionNotes
Convolution + bias
k×k, stride s, padding p		y[o, i, j] = b[o] + Σc=0..Cin−1 Σu=0..k−1 Σv=0..k−1 w[o, c, u, v] · x[c, s·i + u − p, s·j + v − p]
Hout = ⌊(H + 2p − k) / s⌋ + 1		x outside the map counts as 0. Each output value uses Cin·k·k multiplications. 3×3 uses p = 1; 1×1 uses p = 0. Stride 2 halves H and W.
Depthwise convolution + bias [11]
k×k, stride 1, padding p		y[c, i, j] = b[c] + Σu=0..k−1 Σv=0..k−1 w[c, u, v] · x[c, i + u − p, j + v − p]Each channel is filtered on its own: k·k multiplications per output value. Followed by a 1×1 convolution it forms a depthwise-separable convolution (class branch of the detection heads).
Batch normalisation (folded into the convolution) [3]w′[o, …] = γ[o] / √(σ²[o] + ε) · w[o, …]
b′[o] = β[o] − γ[o] · μ[o] / √(σ²[o] + ε)		Done once, before inference. γ, β learned; μ, σ² training statistics. Afterwards only convolution + bias remains.
Sigmoidσ(z) = 1 / (1 + e−z)Output between 0 and 1. Used in SiLU and for the class scores.
SiLU [4] [5]SiLU(z) = z · σ(z) = z / (1 + e−z)Applied to every value separately. Some convolutions of YOLO26 have no activation; the tables mark them.
Residual addy[c, i, j] = x[c, i, j] + f(x)[c, i, j]f is the part that the add goes around (two convolutions of a bottleneck, the attention, the FFN, or SPPF). x and f(x) have equal shapes.
Bottleneck (Cin = Cout = c, expansion e)Bottleneck(x) = x + SiLU(Conv3×3e·c→c(SiLU(Conv3×3c→e·c(x))))e = 0.5 directly inside C3k2 (middle width c/2); e = 1.0 inside C3k. Every YOLO26 bottleneck has the residual add.
C3k unit (input c channels)k = Bottleneck(Bottleneck(SiLU(Conv1×1c→c/2(x))))
y = SiLU(Conv1×1c→c(Concat(k, SiLU(Conv1×1c→c/2(x)))))		A C3 block with 2 bottlenecks (e = 1.0). The second 1×1 convolution reads the block input, in parallel with the bottleneck branch; it does not depend on the bottleneck output. (The reference code evaluates it after the bottleneck branch.) The two outputs are concatenated.
C3k2, n unitsa | b = Split(SiLU(Conv1×1(x)))
m1 = U(b), mk = U(mk−1)
y = SiLU(Conv1×1(Concat(a, b, m1, …, mn)))		U is a bottleneck, a C3k unit, or a bottleneck followed by a PSABlock. Every mk is kept and concatenated, as in C2f.
Channel splita = x[0 .. C/2 − 1, i, j],   b = x[C/2 .. C − 1, i, j]Selects channel ranges; no arithmetic.
Channel concatenationy[c, i, j] = x1[c, i, j] for c < C1;
y[c, i, j] = x2[c − C1, i, j] for C1 ≤ c < C1 + C2; and so on		Stacks maps of equal H and W along channels; no arithmetic.
Max-pool k×k, stride 1, padding py[c, i, j] = maxu, v = 0..k−1 x[c, i + u − p, j + v − p]x outside the map counts as −∞. SPPF uses k = 5, p = 2, so H and W are unchanged.
Nearest upsample ×2y[c, i, j] = x[c, ⌊i / 2⌋, ⌊j / 2⌋]Each value is copied to a 2×2 area; no arithmetic.
Matrix product of two tensors [10]Z[r, t] = Σu X[r, u] · Y[u, t]Both operands are activations computed from the image, not weights. qTk: per attention head, (400×32)(32×400); v·AT: (64×400)(400×400).
Softmax over a row [10]A[r, t] = eZ[r, t] / Σu eZ[r, u]Each row of 400 values becomes positive values that sum to 1. One exponential per value; exponentials and divisions are not counted as multiplications.
Attention, h attention heads [10] [9]q, k, v = Split(Conv1×1(x)) per attention head;   A = softmax((q · dk−1/2)Tk)
y = Conv1×1(v · AT + DWConv3×3(v))		N = H·W positions; q, k have dk = 32 channels, v has 64 channels per attention head. The convolutions here have no activation. The scaling of q is one multiplication per value of q.
PSABlock [12] [9]r = x + Attention(x);   y = r + Conv1×12c→c(SiLU(Conv1×1c→2c(r)))Attention followed by a feed-forward network (FFN), each with a residual add.
Bilinear resize, gain g [7]r = (i + 0.5) / g − 0.5,   q = (j + 0.5) / g − 0.5,   r0 = ⌊r⌋, q0 = ⌊q⌋, α = r − r0, β = q − q0
y[c, i, j] = (1−α)(1−β)·x[c, r0, q0] + (1−α)β·x[c, r0, q0+1] + α(1−β)·x[c, r0+1, q0] + αβ·x[c, r0+1, q0+1]		A weighted average of the 4 nearest source values. g = min(640 / H, 640 / W).
Padding and scalingy[c, i, j] = 114 outside the resized image; then y / 255Padding fills the 640×640 canvas; scaling maps 0–255 to 0–1.
Channel reordery[c, i, j] = x[2 − c, i, j]BGR to RGB; no arithmetic.
Box from distances [9]cx = j + 0.5, cy = i + 0.5
x1 = (cx − dl)·s, y1 = (cy − dt)·s, x2 = (cx + dr)·s, y2 = (cy + db)·s		s is the stride of the level: 8, 16 or 32. The distances d come straight from the box branch: YOLO26 has no DFL (reg_max = 1), so there is no softmax over bins and no expected value [6]. The one-to-many path gives centre, width and height instead of corners.
Top-k selection [9]I = indices of the k largest values of s,   k = min(max_det, length of s)Used twice on the main path: 300 of 8,400 positions, then 300 of 24,000 (position, class) pairs. Comparisons only.
Gathery[t] = x[I[t]]Copies the selected entries; no arithmetic.
Confidence thresholdkeep if score > τconfτconf is the setting conf (utils/nms.py lines 74 and 86).
IoUw = max(0, min(x2A, x2B) − max(x1A, x1B)), h likewise for y
IoU(A, B) = w·h / (area(A) + area(B) − w·h)		Overlap of two boxes, from 0 (none) to 1 (identical).
Non-maximum suppressionSort boxes by score, highest first. Repeat: keep the first box; remove every remaining box of the same class with IoU > τIoU against itSecondary path only. τIoU is the setting iou. Removes duplicate detections of one object.
Undo the letterboxx = (x′ − padx) / g,   y = (y′ − pady) / gMaps box corners back to the original image.
